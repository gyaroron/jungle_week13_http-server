# 6단계 동시성 모델 비교 요약

동일한 전체 서버 코드에서 연결 분배 방식만 바꾸어 비교했습니다. 서버와 ApacheBench 클라이언트는 같은 Mac에서 실행했습니다. `make clean && make`의 C11 디버그 빌드(`-g -O0`)를 사용했고, 정적 `/` 파일은 169 bytes였습니다. 각 모델을 `ab -n 2000 -c 50 http://127.0.0.1:18080/`로 네 번 측정했습니다. keep-alive 옵션은 사용하지 않았고, 서버 로그는 세 모델 모두 `/dev/null`로 보냈습니다. 전체 출력은 `stage6_models_2026-11-25.txt`에 있습니다.

## 판독

- 순차 브랜치는 `accept()` 다음 `conn_handle()`을 `main` 스레드에서 실행합니다. 한 요청이 끝나기 전에는 그 스레드가 다른 연결을 처리하지 않습니다.
- 연결별 스레드 브랜치는 수락된 연결마다 heap에 저장한 fd를 새 분리 스레드에 넘깁니다. 완료한 스레드는 종료합니다.
- 풀 브랜치는 8개 worker와 고정 원형 대기열을 사용합니다.
- 이 네 번의 Mac 로컬 실행에서는 연결별 스레드와 8-worker 풀의 중앙값이 비슷했습니다. 수치 차이는 이 실험 조건에 한정되며, 모든 시스템에서 한 모델이 더 빠르다는 결론은 내리지 않습니다.
- 순차 기준은 과거 1단계 커밋 원본이 아닙니다. 현재 전체 기능을 유지한 채 dispatch 방식만 순차로 바꾼 통제 기준입니다. 이 설계 차이를 `docs/TUTORIAL_LOG.md`에도 기록합니다.
- ApacheBench는 동일 호스트의 loopback 측정입니다. 네트워크 지연, 원격 클라이언트, 동적 요청 부하는 포함되지 않습니다.
