# 2026-11-26 thread pool vs event loop (-e) · feature/event-loop

같은 빌드(make 기본 -O0 debug)를 같은 세션에서 모드만 바꿔 측정했다. macOS loopback, 정적 `/` 169 bytes, 서버 로그는 /dev/null, ulimit -n 4096.
처리량: `ab -q [-k] -n 10000 -c 100 http://127.0.0.1:PORT/`, 조건별 3회.
idle 검사: python으로 keep-alive 연결 N개를 열어 각각 요청 1개를 보내고 응답을 받은 뒤 열어 둔 채, 2.5초 뒤 curl로 새 GET 1개의 시간과 상태 코드를 쟀다(-w 8, 조건별 1회).

## 해석
- pool w=8 idle: 136 = worker 8 + 대기열 128. 이 수를 넘는 연결과 새 GET은 pool_submit()의 EAGAIN 경로로 503을 받았다.
- event w=8 idle: 쉬는 연결은 kqueue가 감시하고 worker를 붙잡지 않으므로 200개 · 1000개 모두 응답을 받았고 새 GET도 200이었다.
- event 모드의 Linux epoll 경로는 이 Mac에서 빌드 · 실행하지 못했다. stub 헤더로 형식 검사(-fsyntax-only)만 통과했다.
