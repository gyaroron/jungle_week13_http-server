# C 웹서버 · 프록시

macOS에서 C와 POSIX 소켓 API로 만든 학습용 HTTP 서버입니다. 정적 파일과 CGI를 제공하고, 설정 파일에 따라 리버스 프록시와 `-f` 포워드 프록시를 실행합니다. 로컬 브랜치에서 연결을 순차 처리하거나, 연결마다 스레드 하나를 만들거나, 8개 worker 스레드 풀로 처리할 수 있습니다. 세 모델은 공통 `conn_handle()`을 사용하므로 7-6 GET 캐시 동작도 같습니다.

## 빌드와 실행

```sh
make
./build/server
```

| 인자 | 기본값 | 기능 |
|---|---:|---|
| `-p PORT` | `8080` | 서버가 듣는 포트 |
| `-r ROOT` | `./www` | 정적 파일과 CGI의 문서 루트 |
| `-b BACKLOG` | `128` | 커널의 연결 대기열 크기 힌트 |
| `-w WORKERS` | `8` | 스레드 풀의 일꾼 수 (1–256) |
| `-t SECONDS` | `5` | 클라이언트·업스트림 소켓 제한 시간 |
| `-c FILE` | 없음 | 리버스 프록시 규칙 파일 |
| `-f` | 꺼짐 | HTTP 포워드 프록시 사용 |
| `-h` | — | 사용법 출력 |

종료할 때는 `Ctrl+C`를 누릅니다. 서버는 새 연결 수락을 중단하고 대기열에 들어온 연결을 처리한 뒤 일꾼 스레드를 정리합니다.

## 요청 처리 흐름

1. `main.c`가 인자를 읽고 듣는 소켓을 준비합니다.
2. `accept()`가 클라이언트 연결을 받아 새 연결 소켓 번호를 만듭니다.
3. `pool.c`의 고정 스레드 풀이 연결 번호를 일꾼에게 넘깁니다.
4. `conn.c`가 요청을 읽고 `http.c`가 요청 줄·헤더·본문 경계를 해석합니다.
5. absolute-form HTTP 요청은 `-f` 설정에서 포워드 프록시로 전달합니다. 나머지는 라우팅 규칙에 맞으면 리버스 프록시로 보내고, 맞는 규칙이 없으면 CGI 또는 정적 파일로 처리합니다.
6. 응답을 보낸 뒤 연결을 유지하거나 닫습니다. 설정 제한 시간, 오류 응답, 프록시 연결은 연결 종료 경로를 사용합니다.

| `src/net.c` | 소켓 생성, 주소 연결, 시간 제한, 끝까지 보내기 |

| `src/http.c` | HTTP 요청 파서 |
| `src/config.c` | 명령줄 설정 |
| `src/response.c`, `src/mime.c`, `src/static.c` | 응답, MIME 형식, 정적 파일 |
| `src/cgi.c` | CGI 자식 프로세스 실행과 출력 중계 |

| `scripts/functional_test.sh` | 기능·동시 접속·자원 정리 검사 |

## 리버스 프록시 규칙

`routes.conf.example` 형식을 사용합니다. 한 줄은 `HOST PREFIX BACKEND...`입니다.

```text
* /api/ 127.0.0.1:8001 127.0.0.1:8002
```

```sh
./build/server -c routes.conf.example
./build/server -c routes.conf.example -f
```

호스트와 경로 접두사가 모두 맞는 규칙 중 더 긴 접두사를 선택합니다. 같은 규칙에 백엔드가 여러 개면 라운드 로빈으로 선택합니다.

## GET 응답 캐시

`GET` 요청 중 캐시 가능한 요청은 절대 URL을 키로 조회합니다. 첫 요청은
원래 경로(리버스 프록시 백엔드 또는 정적 파일)에서 응답을 받아
`X-Cache: MISS`를 표시하고, 완전한 `200` 응답만 캐시에 저장합니다.
같은 URL의 다음 요청은 저장된 응답을 사용해 `X-Cache: HIT`를 표시합니다.
캐시는 최대 64개 응답, 응답 하나당 256 KiB, 전체 8 MiB로 제한하고
뮤텍스로 보호합니다. 공간이 부족하면 먼저 들어온 오래된 항목부터 버립니다.

`Authorization`, `Cookie`, `Range`, 조건부 요청 헤더가 있는 요청은 캐시를
우회합니다. 응답에 `Set-Cookie`, `Vary`, `Transfer-Encoding`,
`Cache-Control: private` 또는 `no-store`가 있으면 저장하지 않습니다.
미스나 저장 불가 응답은 백엔드 또는 디스크에서 직접 처리합니다.
이 학습용 캐시에는 만료 시간과 쓰기 요청에 따른 무효화가 없으므로,
백엔드나 파일이 바뀌면 서버를 재시작해 캐시를 비워야 합니다.

## 구현 범위와 제한

- HTTP/1.0과 HTTP/1.1 요청, `GET`·`POST`, `Content-Length` 본문, 연결 유지, 정적 파일, CGI를 지원합니다.
- 리버스 프록시는 `Host`와 경로 접두사로 백엔드를 선택하고, 연결 실패에는 502, 연결·첫 응답 제한 시간에는 504를 보냅니다.
- `-f`는 `http://` absolute-form 요청을 전달합니다.
- 청크 방식 본문(Transfer-Encoding)은 지원하지 않습니다.
- HTTPS 터널을 만드는 `CONNECT`는 501로 거절합니다. `https://` absolute-form도 400으로 거절합니다.
- TLS, 큰 요청의 무제한 스트리밍은 구현 범위 밖입니다. 요청 헤더와 본문에는 고정 상한이 있습니다.
- 스레드 하나가 연결 하나를 맡아 연결이 닫힐 때까지 처리합니다. 따라서 keep-alive 연결이 많으면 각 연결이 일꾼을 점유합니다. 부하 측정에서 기본 8개 일꾼은 동시 100개 keep-alive 요청을 잘 처리하지 못했습니다. 일꾼을 128개로 설정한 같은 측정에서는 실패가 0건이었습니다. 실제 배포에 적합한 값이라는 뜻은 아니며 이 수치는 이 Mac에서 수행한 로컬 학습 측정입니다.
- macOS에서 빌드와 검사를 확인했습니다. Linux 빌드는 실행하지 않았습니다.

## 검사

```sh
make test
./scripts/functional_test.sh
make test-asan
make asan
make tsan
```

`make test`는 파서·MIME·라우팅 단위 검사를 실행합니다. 기능 스크립트는 정적 파일, CGI, 리버스·포워드 프록시, 오류 응답, 동시 접속 20개, 클라이언트 중도 종료, 파일 디스크립터 수와 좀비 프로세스 수를 검사합니다. 실제 실행 결과와 ApacheBench 측정 전문은 [`docs/TUTORIAL_LOG.md`](docs/TUTORIAL_LOG.md)와 [`docs/benchmarks/apachebench_2026-11-25.txt`](docs/benchmarks/apachebench_2026-11-25.txt)에 기록했습니다.

## 코드 작성 방식

이 프로젝트의 코드는 사용자의 지시에 따라 Codex가 작성·수정했습니다. 사용자는 설계 우선순위와 학습 범위를 정했고, 실행 환경의 터미널 결과를 공유했습니다. 빌드·검사와 성능 숫자는 실행한 결과만 기록했습니다.
